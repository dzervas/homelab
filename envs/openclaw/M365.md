# M365 mailbox access (Graph, app-only)

OpenClaw reads and tags mail through Microsoft Graph as an app limited to one mailbox.
`main.jsonnet` maps these `hermes-workspace` 1Password fields to env vars:

| 1Password field      | Env var               |
| -------------------- | --------------------- |
| `m365-tenant-id`     | `AZURE_TENANT_ID`     |
| `m365-client-id`     | `AZURE_CLIENT_ID`     |
| `m365-client-secret` | `AZURE_CLIENT_SECRET` |

Never grant `Mail.ReadWrite` in Entra. Entra and Exchange grants add together,
so a grant in Entra would give access to every mailbox.

## 1. Entra app (entra.microsoft.com)

1. App registrations → New registration: `openclaw-mail`, single tenant, no redirect URI.
2. Overview: client ID → `m365-client-id`, tenant ID → `m365-tenant-id`.
3. Certificates & secrets → New client secret (24 months max): Value → `m365-client-secret`.
   Note the expiry date.
4. API permissions: remove `User.Read`, add nothing.
5. Enterprise applications → `openclaw-mail`: note the Application ID and **Object ID**
   (the App registrations Object ID is a different value).

## 2. Mailbox scope (Exchange Online PowerShell)

```sh
nix shell nixpkgs#powershell -c pwsh
```

```powershell
Install-Module ExchangeOnlineManagement -Scope CurrentUser
Connect-ExchangeOnline -UserPrincipalName <admin-upn>   # or -Device

New-ServicePrincipal -AppId <app-id> -ObjectId <enterprise-app-object-id> -DisplayName "openclaw-mail"
New-ManagementScope -Name "openclaw-mailbox" -RecipientRestrictionFilter "PrimarySmtpAddress -eq '<mailbox>'"
New-ManagementRoleAssignment -Name "openclaw-mail-rw" -Role "Application Mail.ReadWrite" `
  -App <app-id> -CustomResourceScope "openclaw-mailbox"

Test-ServicePrincipalAuthorization -Identity <app-id> -Resource <mailbox>   # InScope: True
Test-ServicePrincipalAuthorization -Identity <app-id> -Resource <other>     # InScope: False
```

Changes take 30 min to 2 h to reach Graph. The test cmdlet doesn't wait for that.

## 3. Deploy

1. Add the three fields to the `hermes-workspace` 1Password item.
2. `tk diff envs/openclaw`, then `tk apply envs/openclaw`, then restart the pod (env vars are read at startup).
3. Call Graph via `/users/<mailbox>/...`; `/me` doesn't work with app-only tokens.
4. Create category names once in Outlook; `Mail.ReadWrite` can't add them to the master list.

## Alter

- Change mailbox: `Set-ManagementScope -Identity "openclaw-mailbox" -RecipientRestrictionFilter "PrimarySmtpAddress -eq '<new>'"`
- Add permission (e.g. send): another `New-ManagementRoleAssignment` with `-Role "Application Mail.Send"`, same scope.
- Rotate secret: new client secret in Entra → update `m365-client-secret` → restart pod → delete old secret.
- Remove: delete the Entra app; the Exchange service principal and role assignments go with it,
  then `Remove-ManagementScope "openclaw-mailbox"`.
